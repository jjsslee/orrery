# CloudWatch 모니터링 구현 계획

작성일: 2026-10-23
상태: 0~3단계 구현과 4단계 로컬 통합 검증을 완료했다. 승인된 Lambda 2개의 제한 실계정 SDK 대조 및 실제 지표 UI 확인을 통과했다. AWS 콘솔 UI 대조·Windows/Intel Mac 실행 등 아래 미완료 항목이 남아 있다.

## 목표와 범위

Orrery에 독립 `모니터링` 메뉴를 추가한다. 사용자가 관심 서비스의 문제를 발견하고, 관련 지표를 같은 시간대로 비교한 뒤 경보·로그·지도에서 근거를 확인할 수 있게 한다.

- 기존 `토폴로지`, `유형별` 화면과 AWS 프로필·리전 선택을 유지한다.
- 각 PC의 자격증명으로 동작하는 로컬 앱을 유지한다.
- 첫 출시는 개요·지표·경보와 관심 자원 묶음을 포함한다. 로그는 후속 단계로 구현한다.
- 24시간 감지와 외부 통지는 기존 AWS 경보가 담당한다. Orrery의 자동 갱신은 화면이 활성화된 동안의 조회 기능이다.
- AWS 경보 생성·수정, 에이전트 설치, 인프라 배포, 외부 알림 전송은 범위 밖이다.
- 다중 계정·리전 통합 화면, 자체 시계열 DB, AI 원인 판정, 사용자 정의 쿼리 편집기는 첫 출시에서 제외한다.
- 현재는 아래 단계에 따라 기능을 구현한다. 이 작업에 한해 `gs-parnas-dev`에서 누적 예상 비용 $10 이하의 자율 조회를 승인받았다. 대상·기간·요청 상한과 실행 결과를 기록하며, 승인 범위나 비용 상한을 초과하려면 새 승인을 받는다. AWS 자원 변경·커밋·푸시·배포·교차 모델 리뷰는 포함하지 않는다.

## 사용자 경험

상단 메뉴: `토폴로지 | 유형별 | 모니터링`.

모니터링 공통 컨트롤:

- 프로필·리전은 기존 공통 선택을 사용한다.
- 기간: 최근 1시간 / 3시간 / 24시간 / 7일 / 직접 선택. 기본 3시간.
- 자동 갱신: 꺼짐 / 1분 / 5분. 최초 기본 꺼짐, 켤 때 기본 선택은 5분.
- 고정된 과거 기간에는 자동 갱신을 적용하지 않는다.
- 지표 조회 시각과 최신 데이터 시각을 구분한다. 갱신 간격을 데이터 해상도로 표현하지 않는다.
- 지도 라이브는 자원 상태·구성 갱신, 모니터링 자동 갱신은 선택 지표 조회로 문구와 동작을 구분한다. 공통 경보 요청은 중복되지 않게 한다.

### 개요

- 발생 중 경보, 데이터 부족 경보, 조회 문제를 먼저 보여준다.
- 관심 자원 묶음 카드와 마지막 확인 시각을 제공한다.
- 경보가 없는 자원 묶음은 `발생 중 경보 없음`으로 표현한다. 관측 범위가 부족한데 서비스 정상으로 단정하지 않는다.
- 각 항목에서 지표·경보 상세·지도 이동으로 이어진다.

### 관심 자원 묶음

- 이름 + 태그 조건 + 수동 포함 자원으로 저장한다. 태그 조건과 수동 포함의 합집합을 사용한다.
- 예: `위키 수집`, `음성 분석`, `고객 대시보드`.
- 연결된 이웃 자원은 추가 후보로 제시하고 사용자가 선택한다. 추론한 관계만으로 자동 포함하지 않는다.
- 프로필 식별자/account/region별로 로컬 저장한다. 삭제된 자원은 `찾을 수 없음`, 태그 신규 매칭은 현재 구성 조회 결과 기준으로 반영한다.
- 첫 버전은 동일 브라우저·origin의 localStorage에 버전 있는 설정으로 저장한다. 다른 PC/브라우저 동기화는 지원하지 않으며 AWS 데이터·로그 본문은 설정에 저장하지 않는다.

### 지표

- 유형별 추천 지표를 기본 제공하고 자원을 선택하면 자동 구성한다.
- 초기 상세 프리셋: Lambda / SQS / ALB / ECS / EC2 / RDS. 나머지는 기존 카탈로그를 유지하되 미지원 지표를 숨기거나 이유를 표시한다.
- 추천 항목: 요청량, 오류 건수·비율, 지연, CPU/메모리(제공되는 경우), 큐 적체·대기 시간.
- 오류율은 같은 기간·대상·집계 단위의 분자/분모로 계산한다. 호출 0은 오류율 0%와 구별한다. p95는 해당 서비스에서 지원되는 지표만 사용한다.
- 같은 시간축과 툴팁을 공유하고 구간을 확대할 수 있다. 서로 다른 단위는 같은 Y축에 겹치지 않는다.
- 첫 버전 비교는 최대 4개 자원, 한 요청 최대 100개 지표 쿼리로 제한한다. 초기 운영값이며 실데이터 부하 확인 후 조정한다.
- `트래픽 %` 상대 정규화 값은 건강 점수나 연결별 실측값으로 사용하지 않는다.

### 경보

- 전체 경보를 ALARM / OK / INSUFFICIENT_DATA로 필터하고 검색한다.
- 이름, 상태 이유, 상태 변경 시각, 임계값·평가 주기·missing-data 처리, 관련 자원, 경보 유형을 표시한다.
- 상세에서 조건과 최근 상태 이력을 제공한다. 이력은 AWS가 반환하는 범위이며 무제한 보존을 약속하지 않는다.
- 자원 매핑 실패는 경보 제거 사유가 아니다. 복합 경보와 지원하지 않는 수식은 원문 조건과 해석 한계를 표시한다.
- CloudFront처럼 지표 리전이 다른 경우 조회 리전을 명시하고, 관련 글로벌 경보 조회 범위를 별도로 설명한다.

### 지도 연계

- `지도에서 보기`는 기존 locate 기능을 이용한다.
- 모니터링의 기간·관심 묶음·선택 상태를 보존해 돌아왔을 때 탐색을 이어간다.
- 환경 변수/정책 등으로 추정한 연결과 직접 확인한 관계를 원인 판정에 혼용하지 않는다. 자동 원인 확정은 하지 않는다.

## 구현 구조

```text
모니터링 화면 / 전용 상태
          ↓
모니터링 API: 입력 검증 / 요청 병합 / 캐시 / 결과 상태
          ↓
경량 자원 인덱스 ─ 지표 카탈로그 ─ 경보 저장 모델
          ↓
기존 인증 소스 / SDK 클라이언트 / 읽기 전용 가드
          ↓
CloudWatch 및 필요한 자원 목록 API
```

- `shared`에 MonitoringScope, MetricQuery/Result, AlarmRecord, SavedResourceGroup에 해당하는 타입을 둔다. 표시 라벨과 데이터 식별자를 분리한다.
- 자원 키는 account/region/type/nativeId를 포함한다. 지표 키는 account/region/namespace/name/정렬한 dimensions/stat/period를 포함한다.
- 자원 기본 상태와 경보 상태, 데이터 수집 상태를 분리한다. 기존 지도 색상은 이 값들에서 파생한다.
- 지표 결과는 요청 범위, period/stat/unit, 상태, 점 배열, 마지막 데이터 시각, 경고를 보존한다. 마지막 성공값을 남길 경우 오래된 값임을 반드시 표시한다.
- Fastify 실행 진입점에서 필요한 route 등록을 분리해 `inject`로 테스트할 수 있게 한다. 전체 서버 구조를 재설계하지 않는다.
- 새 `/api/monitoring/` 아래에 자원 목록·지표 조회·경보 목록·경보 이력 경로를 둔다. 복잡한 조회는 JSON body를 받되 AWS 자원 변경을 의미하지 않는다.
- 서버가 자원 식별자와 카탈로그로 쿼리를 만든다. 첫 버전은 브라우저에서 임의 AWS 명령·임의 SQL/지표 수식을 받지 않는다.
- 지표 조회에는 기간·period·대상 개수 제한을 서버에서 검증한다. 기간이 길어지면 해상도를 낮추며 서비스별 허용 period를 따른다.
- 기존 카탈로그와 실제 CloudWatch dimensions/stat 지원 여부는 프리셋 확장 시 공식 문서와 실데이터로 확인한다. 단순 문자열 테스트만으로 정확성을 인정하지 않는다.
- 모니터링 진입 시 전체 그래프 수집이 필수가 되지 않게 한다. 경보는 즉시 독립 조회하고, 자원 선택에는 해당 유형의 경량 목록만 조회한다. 태그 필터는 수집된 범위와 미수집 범위를 표시한다.
- 페이지별 필요 데이터만 읽는다. 지도와 모니터링에서 같은 데이터 요청은 같은 캐시를 사용한다.
- 캐시 키는 계정·인증 소스·리전·대상·시간 구간·통계·해상도를 모두 구별한다. 상대 시간은 period 경계로 정렬한다.
- 같은 키의 진행 중 조회는 공유한다. 한 화면의 취소가 다른 소비자의 공유 요청까지 중단하지 않도록 한다.
- 자동 갱신은 이전 요청 완료 후 예약한다. 중첩을 막고, 429/일시 오류는 제한된 backoff를 적용한다. 숨김 탭·다른 메뉴·종료 시 중단한다.
- 24시간 감시를 위한 백그라운드 프로세스나 별도 AWS 수집 인프라는 추가하지 않는다.

## 단계별 작업과 완료 조건

### 0. 기존 신뢰도 문제 수정

상태: 구현 완료(실계정 재현·실계정 대조 제외).

구현:

- 자원 기본 상태와 경보 적용 상태를 분리하고, 상태 수집기에 없는 Lambda·SQS를 포함한 전체 자원 인덱스에 경보 발생/해제를 적용한다. 경보 실패는 마지막 성공 경보와 성공 시각을 유지하며 별도 오류를 반환한다. 전체 재수집 중 경보 실패도 같은 스냅샷을 보존한다.
- 지표마다 `complete` / `empty` / `partial` / `error`, AWS 메시지, 실제 period/시작·종료/조회 시각/마지막 데이터 시각/조회 리전을 반환한다. 0은 유효한 값이다. pagination의 Complete 응답은 앞선 PartialData를 해소하며, 후속 페이지 throttling은 이미 받은 점을 부분 결과로 남긴다.
- assume-role의 baseProfile과 비밀 원문을 제외한 ExternalId 해시를 인증 소스에 포함한다. 캐시는 인증 소스·실제 계정·리전으로 분리하고 파일명은 SHA-256을 사용한다. 세션 안에서 STS 계정 확인과 실제 SDK 호출은 같은 자격증명 스냅샷을 사용한다. 최대 5분 TTL과 임시 자격증명 만료 1분 전 중 먼저 도달한 시점에 다시 인증하며 `reconnect=1`도 지원한다. 오래된 pending 실패가 새 세션을 삭제하지 못한다.
- 상태 병합은 구성 캐시의 원래 `storedAt`을 유지하며, 수집 도중 새 그래프가 저장되면 이전 그래프로 덮어쓰지 않는다.
- 프런트의 요청별 세대·AbortController로 늦은 성공·실패·finally를 무시한다. 지도 진입/프로필 변경 시 전체 지표 자동 조회를 제거하고 **전체 지표 조회**를 명시적으로 눌러야 조회한다.
- Inspector는 실제 기간·집계 주기/결과 상태를 표시하고 차트는 단일 점·기간 내 위치·누락 구간을 구분한다.

### 1. 독립 모니터링 기반과 경보

상태: 서버 API·웹 경보 화면 및 fixture 검증 완료.

- `registerMonitoringRoutes`를 Fastify 진입점에서 분리하여 전체 그래프 수집 없는 경보/경량 자원/이력 API를 `inject`로 검증한다.
- 경보는 미연결·복합 경보와 모든 MetricStat를 보존한다. 지도와 모니터링은 인증 소스·계정·리전별 경보 저장소와 진행 중 요청을 공유한다. 다중 지표가 한 자원에 매핑되어도 같은 경보는 한 번만 센다.
- 경보 목록은 현재 선택 리전만 조회한다. CloudFront 글로벌 경보는 `us-east-1`로 리전을 바꿔 확인하며, 독립 6유형 목록에는 CloudFront가 없다. 기존 지도 카탈로그의 CloudFront 지표는 `us-east-1`에서 조회한다.
- 독립 경량 자원 인덱스는 Lambda / SQS / ALB / ECS service / EC2 / RDS instance의 6유형을 우선 지원한다. 다른 유형은 기존 지도 지표 카탈로그를 유지하며, 독립 선택 목록에 지원된 것으로 표시하지 않는다.
- 서버 `inject`/fixture 6개: 독립 진입·복합/미연결 보존·요청 공유, 실패/성공 복구, 다중 MetricStat 0~N 매핑, 유형 검증·태그 권한 실패, 자원 pagination 부분 결과, 경보 이력 기간 제한/페이지 토큰을 확인했다. 서버 typecheck 통과. AWS 실계정 호출 없음.

작업: 메뉴·전용 상태·공통 시간 선택, 경보 API/전체 목록/상세/이력, 빈 화면·권한 오류·부분 실패 UI. 경량 자원 인덱스와 지도 이동.

검증: 전체 그래프를 먼저 수집하지 않아도 경보 메뉴가 열린다. 미연결·복합 경보가 남는다. 메뉴 이동과 프로필 변경이 기존 화면에 회귀를 만들지 않는다.

완료 조건: 독립 경보 화면으로 이미 운영에 사용할 수 있다.

### 2. 지표 탐색과 비교

상태: 서버 API·웹 비교 화면 및 fixture 검증 완료. 제한된 Lambda 실계정 SDK 대조 통과, AWS 콘솔 화면 대조 미검증.

- `MetricsRepository`는 현재 인증 범위에서 조회한 자원만 최대 4개/100지표로 받아 서버 카탈로그에서 AWS 쿼리를 구성한다. Lambda 호출/오류/평균 실행 시간과 지원하는 p95, 분모 0을 계산하지 않는 파생 오류율을 포함한다.
- 기간은 최대 7일이며 과거 데이터 보존 해상도를 고려한다. 기본 period는 3시간 이내 60초, 24시간 이내 300초, 이후 900초이고 EC2 basic monitoring/S3 등 서비스별 최소 period를 적용한다. 시작·끝은 실제 period 경계에 맞춘다.
- 범위·지표·통계·해상도를 캐시 키에 포함하며 동일 진행 요청을 공유한다. 요청당 최대 10개 SDK command로 제한하고 SDK retry(maxAttempts 8)를 포함한 HTTP 시도는 최대 80회임을 구별한다. 이 제한은 AWS 비용 보장을 뜻하지 않는다.
- AWS 공식 문서 대조: MetricDataResult의 Complete/PartialData/InternalError/Forbidden 및 NextToken 의미, 15~63일 데이터의 300초 배수/63일 이후 3600초 배수, Lambda Duration p95와 Errors/Invocations Sum, ALB TargetResponseTime Average/p95와 LoadBalancer dimension을 확인했다. ECS CPU/Memory는 ClusterName+ServiceName이며 RUNNING task가 없으면 데이터가 없을 수 있고, EC2 기본 모니터링은 5분/상세는 1분이다. RDS DBInstanceIdentifier, S3 일 단위 Average·StorageType, CloudFront us-east-1·Region=Global도 문서 대조했다. 이 결과는 서비스 문서 검증이며 실계정/콘솔 대조를 대신하지 않는다.
- 승인 전 준비한 `scripts/verify-cloudwatch-monitoring.ts`는 기본 dry-run이며 AWS 호출을 하지 않는다. 명시 승인 후에만 `gs-parnas-dev`/`ap-northeast-2`의 Lambda 2개(`ninetree-cx-batch-dev`, `parnas-stt-console`), 최근 3시간·60초, 각 Invocations Sum/Errors Sum/Duration Average의 6개 쿼리를 앱 함수와 직접 SDK로 대조한다. harness는 같은 자격증명 스냅샷으로 무료 STS 1회로 승인 계정 일치를 확인한 뒤 재시도 0(maxAttempts 1), pagination 포함 총 CloudWatch 전송 2회 상한을 별도로 강제한다. dry-run(0호출) 및 standalone TypeScript 검사를 통과한 뒤 사용자의 총 $10 이하 승인 범위에서 제한 실계정 검증을 한 번 실행했다. 실제 전송은 무료 STS 1회와 CloudWatch 2회(각 6지표), 재시도 0회다. 2026-10-23 공식 AWS 가격 문서에서 확인한 지표 1,000개당 $0.01 기준 예상액은 약 $0.00012이며, 청구서 실측값이 아니고 세금·환율·기타 별도 요청은 포함하지 않는다.

작업: 선택 대상 지표 API, 기간/해상도 처리, 프리셋, 공유 시간축 차트·구간 확대, 지표별 조회 결과 표시. 기존 Inspector의 기간·결측 표시 개선.

검증: 지표 dimensions/stat, 요청 범위, 부분 응답, 결측, 단일 점, 분모 0, 오래된 데이터, CloudFront 리전, S3 일 단위 지표. 실제 화면에서 축·툴팁·단위·시간대 확인.

완료 조건: 관련 자원 최대 4개를 같은 시간대로 비교하고 AWS 콘솔의 같은 조건 결과와 대조할 수 있다.

### 3. 관심 자원 묶음·개요·자동 갱신

상태: 구현 및 fixture 검증 완료. 실제 계정에서 자동 반복 조회는 실행하지 않음.

- 개요는 발생 중/데이터 부족 경보와 조회 문제를 구분한다. 관심 묶음은 태그 조건과 수동 포함의 합집합이며 source/account/region별 버전 1 설정으로 localStorage에 저장한다. 미조회·실패한 유형, 태그 미조회, 찾을 수 없는 수동 자원을 별도로 표시하고 관측 범위가 부족하면 `발생 중 경보 없음`으로 단정하지 않는다.
- 기존 그래프가 있을 때에만 이웃 자원을 수동 포함 후보로 제시하며 자동 포함/원인 확정하지 않는다. 지도 왕복 시 기간·선택을 보존한다.
- 자동 갱신은 기본 꺼짐, 켤 때 5분이며 1분/5분을 지원한다. 지표 하위 화면·보이는 탭에서만 동작하고 이전 요청 완료 후 예약한다. 429/일시 서버 오류·스로틀링·부분 결과는 2배·4배(최대 20분) backoff를 사용한다. 인증/권한/만료 오류, 잘못된 조건·알 수 없는 오류는 자동 갱신을 끄고 재연결·조건 확인을 안내한다. 고정 과거 기간·메뉴 이동·숨김에서 예약/브라우저 요청을 중단하며 시작된 서버 공유 조회는 완료될 수 있다.
- 같은 프로필에서 다른 계정의 응답이 확인되면 기존 진행 중 요청을 취소하고 선택·데이터를 초기화하여 다시 권한을 확인하도록 안내한다. 묶음 저장/복원·scope 분리, 관측 부족 3건, scheduler 중첩/실패 backoff, 요청 경합을 포함한 웹 테스트 27개 및 웹 typecheck를 통과했다. 최종 전체 통합 결과는 4단계에 기록했다.

작업: 태그/수동 묶음 저장, 개요 카드, 1분/5분 갱신, 요청 병합·가시성 중단, 조회량 안내, 설정 복원.

## 후속: 로그 조사

- Lambda/ECS의 실제 설정을 통해 로그 그룹을 연결하고, 자동 연결 불가 시 사용자가 선택한다.
- 자원과 선택 시간 범위를 이어받아 최근 로그/오류 조회 프리셋을 제공한다. 첫 버전 자유 쿼리 편집기는 제외한다.
- 명시적 조회 버튼으로만 Logs Insights를 실행한다. 최초 기본 최근 15분, 최대 24시간·로그 그룹 5개로 시작한다.
- StartQuery/GetQueryResults/StopQuery를 서비스와 명령 단위로 제한한다. 현재 가드의 `Start*`/`Stop*` 전체 허용은 하지 않는다.
- 실행 중·완료·부분 결과·실패·취소를 구분하고 스캔량을 표시한다. 시간/그룹 제한과 취소는 비용 상한 보장이 아님을 명확히 한다.
- 로그 본문을 로컬 파일·서버 로그에 자동 저장하지 않는다. 외부 AI 전송은 포함하지 않는다.
- 별도 검증: 취소 뒤 결과 경합, 권한 거부, 빈 로그 그룹, 만료 세션, 실행 제한, 가드 허용/차단.

## 성공 판단

- 사용자 점검 시나리오: 경보 발견 → 관련 지표 비교 → 선택 구간 확인 → 관련 자원 지도 이동을 화면 내에서 완료한다.
- 관측되지 않은 상태를 정상으로 오인하지 않는다.
- 선택한 자원 범위 밖으로 지표 요청이 확장되지 않는다.
- 이전 계정/시간 범위의 늦은 응답이 현재 화면을 덮지 않는다.
- 앱 종료 중 감시와 알림을 제공한다고 표시하지 않는다.
- 실제 성능/조회 비용은 실데이터 검증에서 계측하며, 측정 전 수치로 보장하지 않는다.

## 추가 개선: 태그 탐색과 모니터링 작업 화면 (v0.2.0)

사용자 요청에 따라 자원 찾기에 직접 태그 조회 UI를 추가하고, 개요·지표·자원 선택 화면을 개선했다.

- 자원 찾기: 이름/식별자 검색, 태그 키·값 조건(같은 키 OR/다른 키 AND), 태그 없는 자원/권한 등으로 태그를 조회하지 못한 자원 구분. 태그 없는 자원 보기로 바꿔도 태그 조건과 수동 선택을 유지한다.
- 지원 6유형 조회는 명시적 클릭으로 유형별 목록을 순차 조회한다. 토폴로지·지표 조회로 확장하지 않으며 메뉴 이탈·계정/프로필 변경 시 후속 조회를 멈춘다.
- 자원 찾기에서 태그 조건과 수동 자원을 합쳐 묶음 이름을 정하고 저장할 수 있다. 묶음 수동 포함과 최대 4개 지표 비교 선택을 분리했다. 검색 조건과 묶음 초안은 인증 범위 변경 시 비운다.
- 개요: 경보/데이터 부족/조회 자원 요약, 우선 확인할 경보, 현재 경보의 최근 상태 변경, 태그 조건이 보이는 관심 묶음 카드. 경보 원문 상태/조회 범위 의미를 유지한다.
- 지표: 두 열 반응형 차트, 표시 지표 검색, 오류·부분 결과·빈 결과·지연된 지표만 골라 보기. 표시 필터는 추가 AWS 조회를 하지 않는다.
